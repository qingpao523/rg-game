## 1. 文档目标

本文只整理已确认的 MVP 战斗构筑方向，并规划一个可执行的 Demo 版本。

本阶段目标不是补全完整商业版本，而是尽快验证以下问题：

- 5 个 MVP 职业是否有明确手感差异。
- 随机三选一技能是否能形成有效构筑判断。
- 技能进化是否能制造“流派成型”的爽点。
- 单局节奏、暂停、结算、宝藏哥布林是否能支撑基础循环。

## 2. 当前确认范围

### 2.1 MVP 战斗构筑优先级

MVP 采用“职业主动技 + 基础技能构筑”的混合驱动方案。

- 职业主动技负责角色手感、操作上限和职业辨识度。
- 基础技能负责局内构筑、随机选择和流派组合。
- 技能进化负责中后期构筑成型反馈。

暂不纳入本阶段：

- 实时联网、异步 PVP、竞技 CR。
- 全职业 10/20/30 级完整天赋树。
- 付费、皮肤、赛季、排行榜。
- 15 个职业的完整量产内容。
- 魔契之书的完整契约池。

## 3. MVP 职业主动技

Demo 阶段只验证 5 个职业：道士、武士、法老、寒冰女巫、十字军。

| 职业 | 主动技 | 核心效果 | 玩法定位 |
| --- | --- | --- | --- |
| 道士 | 敕令雷符 | 向指定方向落雷，命中后弹射；若触发暴击，则额外触发一次小落雷 | 中距离爆发，适配暴击与雷系构筑 |
| 武士 | 一闪 | 向目标方向突进斩击，期间短暂无敌；击杀敌人返还部分冷却 | 高操作近战，适配击杀连锁与近战爆发 |
| 法老 | 冥棺敕命 | 召回所有召唤物并造成范围冲击，随后刷新一只强化木乃伊 | 召唤调度，适配召唤物与受击收益 |
| 寒冰女巫 | 极寒领域 | 在脚下展开冰域，持续减速并快速叠加冻结；结束时触发碎裂伤害 | 控场法师，适配冰冻、范围和减速构筑 |
| 十字军 | 圣盾冲阵 | 举盾向前推进，击退敌人并吸收伤害；结束时按吸收量造成真伤爆发 | 正面抗压，适配护盾、受击和真伤构筑 |

设计约束：

- 每个主动技必须有清晰的按键收益，避免变成“另一个自动技能”。
- 主动技消耗法力，法力只服务于职业主动技。
- 主动技不要求一开始数值完美，但必须能明显改变职业手感。
- Demo 阶段优先验证手感差异，暂不做复杂升级分支。

## 4. 基础技能结构

### 4.1 技能标签

每个基础技能使用 2-3 个标签描述其构筑身份。

常用标签：

- 元素：火、冰、雷、毒、圣、灾厄。
- 形态：投射、召唤、光环、区域、护盾、附伤。
- 功能：输出、控制、治疗、增益、削弱、续航。

示例：

- 爆裂火球：火 / 投射 / 范围输出。
- 圣光守卫：圣 / 召唤 / 治疗。
- 冰霜结界：冰 / 护盾反击 / 控制。
- 感电烙印：雷 / 附伤 / 连锁催化。

### 4.2 技能升级规则

基础技能暂定最高 Lv5。

升级只强化一个主轴，避免 Demo 阶段数值表失控：

- 伤害提升。
- 冷却降低。
- 数量增加。
- 范围扩大。
- 持续时间延长。
- 触发概率提升。

技能升级不改变技能机制主体。机制变化主要由“进化”承担。

### 4.3 技能类型职责

| 类型 | 数量 | 职责 |
| --- | ---: | --- |
| 召唤类 | 4 | 站场、牵制、召唤流核心组件 |
| 投射/射击类 | 5 | 主输出、清怪、触发元素构筑 |
| 状态/附伤类 | 6 | 流派催化、异常状态、构筑连接件 |
| 恢复/辅助类 | 5 | 续航、容错、召唤物支持、防御补强 |

## 5. 技能进化规则

### 5.1 触发条件

进化采用“主技能 + 催化技能”的规则。

建议规则：

- 主技能达到 Lv5。
- 指定催化技能达到 Lv3 或以上。
- 玩家下一次升级时，三选一中有较高概率出现对应进化项。
- 选择进化后，两个技能合并为一个高级技能，并释放一个技能栏位。

### 5.2 设计目的

- 让玩家能围绕目标进化做构筑判断。
- 让中期出现明确的成型反馈。
- 降低技能栏压力，避免技能越拿越散。
- 让状态类和辅助类技能不只是被动数值，而是关键催化件。

### 5.3 首批推荐进化组合

| 主技能 | 催化技能 | 进化技能 | 效果方向 |
| --- | --- | --- | --- |
| 爆裂火球 | 炎附 | 陨石术 | 大范围火陨石，命中后留下燃烧地面 |
| 分裂冰锥 | 冰霜结界 | 冰棘风暴 | 环绕分裂冰棘，冻结敌人后触发碎裂 |
| 弹射闪电 | 感电烙印 | 雷网审判 | 感电目标之间生成连锁雷网 |
| 穿心毒刺 | 淬毒 | 腐蚀长矛 | 穿透毒矛，毒层满后触发爆毒 |
| 魔法飞弹 | 灾厄光环 | 灾厄飞星 | 追踪飞弹附带抗性削弱 |
| 圣光守卫 | 生命源泉 | 圣泉方尖碑 | 固定治疗塔，周期治疗并净化 |
| 复仇战旗 | 迅捷之风 | 冲锋战旗 | 召唤物攻速、移速提升，击杀延长持续 |
| 钢铁皮肤 | 冰霜结界 | 寒铁壁垒 | 护盾破裂时冻结周围敌人并反伤 |

Demo 阶段不要求全部实现，可优先实现 4 组覆盖主要流派：

- 陨石术：火系输出。
- 冰棘风暴：冰系控制。
- 雷网审判：雷系连锁。
- 圣泉方尖碑：召唤/治疗辅助。

## 6. 微信小游戏 Demo 版本规划

### 6.1 Demo 定位

Demo 版本目标是以微信小游戏形态验证核心战斗循环，而不是展示完整内容量。

建议版本名：`Demo 0.1 - WeChat Core Combat Loop`

目标体验：

- 玩家能选择职业进入战斗。
- 开局获得三选一技能。
- 通过升级持续获得三选一技能。
- 技能可以升级并触发少量进化。
- 怪物压力随时间增强。
- 宝藏哥布林提供风险奖励。
- 玩家死亡后进入结算界面。
- 全程可暂停、可继续。

### 6.2 技术栈

推荐主技术栈：Cocos Creator + TypeScript + 微信小游戏。

| 层级 | 选型 | 说明 |
| --- | --- |
| 引擎 | Cocos Creator 3.8 LTS 优先；若团队确认 4.x 稳定性和插件兼容，再升级 | 2D、小游戏发布、资源分包、编辑器工作流都比较适合本项目 |
| 语言 | TypeScript | 方便做数据驱动、类型约束、战斗系统模块化 |
| 目标平台 | 微信小游戏 | Demo 从第一天就按真机、包体、生命周期约束设计 |
| 渲染 | Cocos 2D / WebGL | 俯视角 2D 生存割草，不使用 3D 管线 |
| 物理/碰撞 | 自研轻量圆形/AABB 碰撞 + 空间网格 | 避免大量怪物和弹幕压垮通用物理系统 |
| 数据配置 | TypeScript config 或 JSON config | 职业、技能、进化、怪物波次全部数据化 |
| 本地存储 | `wx.setStorageSync` / `wx.getStorageSync` 封装 | Demo 只保存设置、最高存活时间、本地统计 |
| 音频 | Cocos AudioSource + 平台适配封装 | 先做关键反馈音效，不做复杂动态音乐 |
| 构建调试 | Cocos 构建微信小游戏 + 微信开发者工具 + 真机预览 | 每个里程碑都要在微信开发者工具和至少一台真机上验证 |

暂不推荐 Unity 作为 Demo 首选。Unity WebGL/小游戏适配适合已有 Unity 项目迁移，但本项目从 0 开始做 2D Demo，Cocos 的包体、启动速度、微信小游戏发布链路和 TypeScript 开发效率更符合当前阶段。

### 6.3 微信小游戏关键约束

Demo 从一开始遵守以下约束：

- 主包必须保持极小，只放启动场景、基础 UI、核心脚本和最低限度资源。
- 地图、角色、怪物、音效、特效图集按 Asset Bundle / 分包管理。
- 微信小游戏不是标准浏览器环境，不能假设 DOM、BOM 或浏览器插件能力存在。
- 必须处理微信生命周期：切后台、来电、锁屏、分享返回时自动暂停或恢复。
- iOS 和 Android 性能差异需要真机验证，不能只看编辑器或开发者工具。
- 所有战斗对象必须对象池化，避免频繁创建销毁带来的 GC 抖动。
- 文字、粒子、伤害数字、掉落物数量必须有限流策略。

包体目标：

- Demo 主包目标控制在 4M 以内。
- Demo 总包目标控制在 30M 以内。
- 首次进入战斗必须不依赖大资源下载；后续正式版本再考虑远程资源。
- 包体上限以发布前微信官方文档、微信开发者工具和 Cocos 当前版本构建结果为准。

### 6.4 Demo 内容范围

| 模块 | Demo 0.1 范围 |
| --- | --- |
| 职业 | 5 个：道士、武士、法老、寒冰女巫、十字军 |
| 地图 | 1 张：破碎龙庭，可先使用灰盒或简化美术 |
| 基础技能 | 建议先实现 12-20 个；若排期紧，至少覆盖 12 个 |
| 进化技能 | 至少 4 个，覆盖火、冰、雷、辅助 |
| 怪物 | 3 类：基础近战怪、冲锋怪、精英怪 |
| 宝藏哥布林 | 1 套完整风险奖励流程 |
| 单局时长 | Demo 目标 8-12 分钟，可压缩完整 25-30 分钟曲线 |
| UI | 职业选择、HUD、升级三选一、暂停、结算 |
| 局外成长 | 暂不实现，结算只展示数据 |

### 6.5 Demo 不做内容

- 不做账号系统。
- 不做联网与排行榜。
- 不做付费与皮肤。
- 不做完整天赋盘。
- 不做全职业内容。
- 不做完整魔契之书。
- 不做正式数值平衡，只做可玩性调参。

## 7. 从 0 开始实现路径

### Step 0：准备开发环境

目标：确保项目从第一天就能跑到微信小游戏环境。

准备项：

- 注册或准备微信小游戏 AppID；早期调试可使用测试 AppID，但正式预览、上传、审核需要真实 AppID。
- 安装 Cocos Creator，优先选择 3.8 LTS。
- 安装微信开发者工具。
- 在 Cocos Creator 偏好设置中配置微信开发者工具路径。
- 创建 2D TypeScript 项目，项目名暂用 `endless-invasion-demo`。
- 建立 Git 仓库，提交空工程和基础目录。

验收标准：

- Cocos 编辑器可运行空场景。
- 可以构建到微信小游戏目录。
- 微信开发者工具可以打开构建产物并运行。
- 真机预览能看到启动画面。

### Step 1：建立工程骨架

目标：先把后续系统边界立住，避免战斗逻辑堆进一个巨型脚本。

建议目录：

```text
assets/
  scenes/
    Boot.scene
    MainMenu.scene
    Battle.scene
    Result.scene
  scripts/
    core/
      GameApp.ts
      GameSession.ts
      TimeService.ts
      EventBus.ts
      ObjectPool.ts
    config/
      CharacterConfig.ts
      SkillConfig.ts
      EvolutionConfig.ts
      EnemyConfig.ts
      WaveConfig.ts
    combat/
      Actor.ts
      Player.ts
      Enemy.ts
      Projectile.ts
      Damage.ts
      CollisionGrid.ts
      StatusEffect.ts
    skill/
      SkillRunner.ts
      SkillInstance.ts
      ActiveAbility.ts
      EvolutionResolver.ts
    spawn/
      WaveDirector.ts
      TreasureGoblinDirector.ts
    ui/
      HudView.ts
      SkillChoiceView.ts
      PauseView.ts
      ResultView.ts
    platform/
      WeChatPlatform.ts
      StorageService.ts
      LifecycleService.ts
  art/
  audio/
  prefabs/
```

核心原则：

- `config/` 只放数据定义，不写运行逻辑。
- `combat/` 只处理战斗实体、伤害、碰撞和状态。
- `skill/` 只处理技能释放、升级、进化和主动技。
- `spawn/` 只处理刷怪节奏和特殊事件。
- `platform/` 隔离微信 API，战斗系统不直接调用 `wx`。

### Step 2：做最小可玩纵切

目标：用最少内容跑通一局“移动、打怪、升级、死亡”。

实现顺序：

1. `Boot.scene` 初始化配置、对象池和平台生命周期。
2. `MainMenu.scene` 只提供开始按钮和基础职业选择。
3. `Battle.scene` 实现玩家移动、相机跟随、基础怪追踪。
4. 实现玩家生命、受击、死亡。
5. 实现自动释放的第一个技能，例如魔法飞弹。
6. 实现经验掉落、升级、三选一 UI。
7. 实现 `Result.scene` 展示存活时间、击杀数、等级。

验收标准：

- 玩家可以在微信开发者工具里完成一局。
- 真机上可持续战斗 3 分钟无崩溃。
- 升级选择能改变战斗表现。

### Step 3：补职业与主动技

目标：验证 5 个职业不是换皮。

实现顺序：

1. 数据化 5 个职业基础属性和被动。
2. 接入法力、主动技按钮、冷却显示。
3. 实现道士 `敕令雷符`。
4. 实现武士 `一闪`。
5. 实现法老 `冥棺敕命`。
6. 实现寒冰女巫 `极寒领域`。
7. 实现十字军 `圣盾冲阵`。

验收标准：

- 每个职业至少能完整跑一局。
- 主动技有明确使用时机。
- 切后台或暂停时，主动技冷却和战斗时间不会继续偷跑。

### Step 4：补技能、升级和进化

目标：验证构筑目标感。

实现顺序：

1. 把基础技能实现到至少 12 个。
2. 每个技能支持 Lv1-Lv5。
3. 技能升级只改数值主轴，不改机制主体。
4. 实现进化检测：主技能 Lv5 + 催化技能 Lv3。
5. 实现 4 个优先进化：陨石术、冰棘风暴、雷网审判、圣泉方尖碑。
6. 进化成功后合并技能栏，并播放明确反馈。

验收标准：

- 玩家能主动追一个进化目标。
- 至少 2 种构筑路线有明显差异。
- 技能数量增加后，真机帧率仍可接受。

### Step 5：补刷怪、宝藏哥布林和闭环

目标：让 Demo 形成完整的一局体验。

实现顺序：

1. `WaveDirector` 实现 8-12 分钟压缩压力曲线。
2. 加入基础怪、冲锋怪、精英怪。
3. `TreasureGoblinDirector` 实现屏幕边缘方向提示、逃跑、消失和击杀奖励。
4. 完成暂停、恢复确认、死亡结算。
5. 加入关键音效和基础特效。

验收标准：

- 单局可从职业选择跑到结算。
- 宝藏哥布林能制造追击风险。
- 至少 3 次完整游玩无阻断 bug。

### Step 6：微信小游戏适配与发布检查

目标：让 Demo 可以稳定预览和内部测试。

实现项：

- 配置微信小游戏构建目标。
- 配置主包和 Asset Bundle / 分包。
- 确认 `game.json`、`project.config.json` 生成正确。
- 接入 `wx.onShow`、`wx.onHide`，切后台自动暂停。
- 接入本地存储，保存最高存活时间和设置项。
- 使用微信开发者工具查看包体、基础库、性能面板。
- 分别在 iOS 和 Android 真机预览测试。

验收标准：

- 主包体积低于 4M。
- Demo 总包体积低于 30M。
- 微信开发者工具可预览。
- iOS 和 Android 真机都能完成一局。
- 切后台、锁屏、返回后状态正确。

## 8. Demo 开发里程碑

### Milestone 1：可移动可战斗原型

目标：证明基础操作和自动战斗能跑起来。

内容：

- Cocos 2D TypeScript 工程。
- 微信小游戏构建链路。
- 角色移动、碰撞、受击、死亡。
- 基础怪生成与追踪。
- 经验掉落与升级。
- 开局三选一技能。
- 至少 3 个基础技能。

验收标准：

- 微信开发者工具可运行。
- 玩家可以进入地图并存活至少 3 分钟。
- 怪物能持续生成并形成压力。
- 升级选择能改变战斗表现。

### Milestone 2：职业手感验证

目标：证明 5 个职业不是换皮。

内容：

- 5 个职业基础属性与被动。
- 5 个职业主动技。
- 法力消耗与主动技冷却。
- 基础 HUD：生命、法力、等级、时间、技能栏。

验收标准：

- 每个职业至少有一种明显优势场景。
- 主动技使用时机影响生存结果。
- 玩家能通过 1-2 局感知职业差异。
- 切后台、暂停、恢复不会破坏主动技状态。

### Milestone 3：构筑与进化验证

目标：证明三选一和进化规则能产生目标感。

内容：

- 12-20 个基础技能。
- 技能 Lv1-Lv5 升级。
- 至少 4 个进化技能。
- 进化提示与选择反馈。

验收标准：

- 玩家能围绕某个进化目标主动选择技能。
- 进化出现时有明显强度和视觉反馈。
- 不同构筑的清怪方式有可感知差异。
- 真机上大量技能和怪物同时存在时，没有明显卡死或失控掉帧。

### Milestone 4：Demo 闭环

目标：形成可对外演示的一局完整体验。

内容：

- 宝藏哥布林机制。
- 8-12 分钟压缩压力曲线。
- 暂停与恢复确认。
- 死亡结算界面。
- 基础音效与关键反馈。

验收标准：

- 单局能从职业选择完整跑到死亡结算。
- 宝藏哥布林能制造明确风险决策。
- 暂停机制稳定，不影响战斗状态。
- 至少 3 次完整游玩无阻断 bug。
- 微信开发者工具和真机预览均可完成一局。

## 9. Demo 成功标准

Demo 0.1 成功不以内容量衡量，而看以下体验是否成立：

- 玩家愿意立刻再开一局。
- 玩家能说出自己这局是什么构筑。
- 玩家能说出职业主动技什么时候救了自己或害了自己。
- 进化技能出现时有明显“成型了”的反馈。
- 宝藏哥布林让玩家愿意冒险离开安全区域。
- 单局失败后，玩家认为失败原因与选择、操作或构筑有关，而不是随机性完全失控。
- 在微信小游戏环境中，启动、暂停、切后台、恢复、结算流程稳定。

## 10. 主要风险与控制

| 风险 | 表现 | 控制方式 |
| --- | --- | --- |
| 内容范围过大 | Demo 迟迟不可玩 | 优先做 5 职业、12 技能、4 进化，剩余内容排后 |
| 职业主动技存在感不足 | 职业像换皮 | 主动技必须有位移、控场、爆发、召唤调度或防御窗口 |
| 三选一选择无脑 | 玩家只选伤害 | 状态/辅助技能绑定关键进化，提升构筑价值 |
| 数值成长失控 | 前期刮痧或后期全屏秒杀 | Demo 使用短局曲线，先按分钟调怪物压力 |
| 进化太随机 | 玩家无法规划 | 主技能 Lv5 + 催化 Lv3 的规则必须可被 UI 表达 |
| 宝藏哥布林打断节奏 | 追击收益或风险不明显 | 加强方向提示、音效和击杀奖励反馈 |
| 微信包体超限 | 无法预览、上传或冷启动过慢 | 主包只放启动必需内容，地图和大资源分包 |
| 真机性能不足 | 大量怪物、弹幕、掉落导致卡顿 | 对象池、空间网格、图集合批、数量上限、伤害数字限流 |
| 微信生命周期问题 | 切后台后时间、冷却、怪物状态错乱 | 用 `LifecycleService` 统一处理 `onShow` / `onHide` 和暂停 |
| 平台 API 污染战斗逻辑 | 后续迁移 PC 或其他平台困难 | 所有 `wx` 调用集中在 `platform/` 层 |

## 11. 后续交付建议

- 核心战斗系统。
- 职业与主动技系统。

- Demo UI 与结算系统。
